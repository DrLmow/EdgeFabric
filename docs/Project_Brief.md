# EdgeFabric 边缘互联

本工程主要集中于边缘设备的互联，边缘设备可以是带有少量传感器的STM32设备，亦或是带有蓝牙WIFI的ESP32模块，或者是嵌入式Linux设备，甚至是手机，电脑，服务器。让这些设备都能够将采集到的信息互相交换，例如自适应网络算法，或者是在某处使用从网络中得到的消息做出一些行为。此互联网络目标是实现一个自组网的通用解决方案。

EdgeFabric，以下简称edf

## 组成部分

1. 边缘设备
   在边缘设备上，edf需提供合适的API（同步，异步等）来满足不同应用的数据采集方式，同时需要提供合适的网络传输API，设备可以通过API来加入已经建立的网络，使得网络可以发现自己，并且向网络传输信息，或者从网络中获取信息。
2. 互联
   互联由多个路由节点组成，路由节点本身可以是边缘设备，也可以只是单纯的路由器。互联主要负责通过网络地edf址定位设备，决定网络中数据流的路由算法，同时负责发现并纠正在传输中出现的错误。
3. 网关
   edf网关是在边缘设备之外的设备，它在网络中的定位不是采集数据——尽管他可以这样做，它负责将网络中的数据流收集，整理，并向服务器上报。同时，它也可以作为网络中的保序点——即它可以实现网络中一些必须按照顺序完成的操作，同时，它可以负责广播信息，发现新设备，定时监测节点状态，定时重启，监测流量状态等
4. 服务器
   在edf语境中，服务器主要指具有大型CPU阵列，内存容量大，具有较高算力的计算机或计算机集群。服务器可以从一个或更多的网关中获取信息——网关和服务器可以是同一台设备，也可以不是同一台设备。服务器可以从网关中获取网络信息，或者通过网关和网络进行交互。服务器端edf会提供合适的API来满足不同的数据处理需求，数据可以被服务器任意使用，包括但不限于使用AI进行分析，网页展示，可视化监测，或者通过其他算法进一步处理。

## 分层

根据功能，可以将本工程分为如下几层：

1. 传感器
   传感器是边缘设备采集数据的硬件模块，传感器不一定是传统的模数转换器，它的目标是任意可以输入数据的设备，包括但不限于摄像头，温度传感器，WiFi模块（检测网络强度），甚至是top（当前系统负载）均可以是传感器。

   ==但是需要注意==，虽然传感器是单独一层，但这并不代表edf负责驱动传感器。传感器之所以要单开一层，是因为传感器的种类对于edf来说是重要的组成部分。由于一个边缘设备可以是互联节点，那么系统负载和网络状态对于这个节点就变得很重要，如果在系统负载较高的状态下仍然向其路由网络包会导致网络整体吞吐量变低。同时，有些节点的电量也很重要，尽管节点休眠会导致系统速度变慢，我们也需要保证某些节点尽可能多的进入低功耗状态，而不是频繁被唤醒来路由网络包，这是一个需要在部署时综合考虑的因素。
2. SoC
   SoC指的是System on Chip，不严谨的讲，可以将其视作主控芯片，例如STM32F103，或者ESP32-C6等，均可以称为是一款SoC。SoC单开一层的作用在于edf可以针对某一款SoC单独做适配，用户可以在不做额外的操作下自动使用肯定已经存在（或大概率存在）的传感器，例如esp32的WiFi&BT。这样做有个好处，如果某款芯片被edf适配了合适的传感器驱动及其API调用，那么这款芯片可以单独就作为某种功能性模块来被大范围使用。例如ESP32可以大范围作为路由器来使用，因为它自带了WiFi的功能。这样的话，EDF本身编译出来的产物就可以直接作为ESP32的固件来直接使用。
3. Board
   Board即开发板，板级的适配要比SoC级别的适配要更加广泛，因为有些功能可能并不是内置于SoC的，但是某些开发板确确实实是为了某些特殊场景而开发的。使用Board层的理由和SoC是几乎一致的，最大的优点就是标准化和快速部署。
4. 网络接口
   网络接口是将边缘设备，网关，甚至是服务器接入网络的硬件设备。合适的网络接口可以大幅提升网络的传输速度。网络接口可以指代一切可以用作互联的数据链路层协议，包括但不限于WiFi，BT，LoRa，以太网，甚至是UART，IIC，SPI。网络接口限制了物理层的特点，物理层的特点直接或间接决定了其上层可以支持的具体传输类型，可以参考的有传输速度，最大传输距离，传输稳定性，以及传输特点。例如UART，BT，LoRa就不适合传输图像，而IIC，SPI几乎不能在米级进行互联，故而也几乎没有办法当做路由节点。选择合适的网络接口可以最大化传输的效率和综合水平。
5. 网络协议
   对应于计算机网络五层，网络协议可以对应到第二层和第三层。无论是传输的具体类型（指具体的传输动作）还是在网络中的具体路由算法，在edf中均属于网络协议层。网络协议负责实现可靠或不可靠的传输，类似于tcp/udp，但是由于边缘设备的受限和网络接口的多样化，edf将会使用多种解决方案，不同的边缘设备可以选择不同的解决方案以满足工程需求。网络路由算法则类似于IP，它主要负责在已经建立的网络中路由网络包，但不同于传统的网络层，edf将会使用更加轻量可替代的方案来满足不同的场景，并且会更加专一，也就是说，不会因为有特殊应用的存在而来添加不必要的额外的功能，例如广播/多播机制，订阅机制，p2p等。这些在edf中会使用各自独立的网络协议模块来实现，多种网络协议可以在网络中同时使用来满足更复杂的应用情况。
6. 上层协议
   上层协议对应于五层中的应用层。由于应用层可以存在于服务器，边缘设备甚至是网关中，所以应用层需要同时考虑效率和算力的需求，例如在边缘设备处的应用层协议不可以过于复杂，尽可能简单来满足需求即可，而网关由于需要将大量的数据聚合在一起来进行运算和处理，所以需要设计算法来在尽可能有限的算力下（尽管已经比边缘设备好太多了）来更好地处理数据，而服务器则没有算力和内存的担忧，对于设计会更宽松（ToDo）
7. 前端
   为了方便可视化，检测，和进一步处理。前端层负责更外层的接口，尽管上层协议已经可以很好的处理这样的需求，但前端层进一步扩展了这样的能力，一些预设的功能可以更加灵活地在服务器或网关上部署，这样向外可以暴露类似于网站网页，或者接收数据的端口，来进一步扩展系统的功能（ToDo）
